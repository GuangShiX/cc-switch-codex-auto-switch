# Windows 管理器存活修复

## 问题与证据

保留日志中，2026-10-12 的两次流程停在 Windows 正常退出调用开始后，2026-10-13 晚间一次停在原生退出请求后，均未继续账号启用。管理器没有正常退出清理记录。日志证明关闭阶段中断，不能单凭日志证明系统终止原因；用户提到的另一次此前事件尚未在保留日志中定位。

此前安装脚本从 Codex 工具进程直接启动 CC Switch。实际工具 Job 有 `KILL_ON_JOB_CLOSE` 限制；隔离实验中，直接启动的测试进程随测试 Job 结束，而经 Explorer 启动的测试进程存活。当前从 Explorer 启动的管理器已成功完成一次手动切号、桌面重开和本聊天恢复。这些证据支持先修复宿主生命周期继承，同时保留两条正常退出路径的严格目标校验。

## 本轮实现

1. 在 Tauri、数据库和后台监测初始化前检测启动归属。只有核实 Codex 桌面祖先并仍属于 Job 时，才尝试一次原生独立启动；不能用最内层 Job 无退出限制来排除外层限制。正常 Explorer 启动保持原路径，不以“属于某个 Job”作为阻挡条件。
2. 原进程先创建独立子进程，再完成确认和提交握手。子进程确认没有继承 Job 后才回应；未收到提交不初始化应用。父进程确认交接后退出，避免两个后台同时查询、启用或恢复。交接失败不循环拉起，保留原实例并记录原因。若已经确认管理器仍受 Codex 管理，桌面流程在暂停任务前停止危险退出；原生手动账号启用保留，不能假装隔离成功后继续关闭宿主。
3. 保留原程序参数、工作目录、配置目录和静默启动设置。没有常驻助手、额外登录管理器或新定时扫描；不触碰账号令牌。
4. 在启动及退出 Codex 前记录受限进程诊断；原聊天恢复记录增加可选关闭意图快照，包含管理器与原桌面身份。关闭意图不等于请求已发送，更不等于退出已确认；旧记录缺字段仍可读取，不因此获得自动重放资格。
5. 安装脚本继续通过已验证的 Explorer 独立入口启动，作为第二层保障。

## 验收顺序

- 源码：启动判定、一次性交接、失败及超时、旧记录兼容、取消与原有恢复保护的回归。
- Windows 隔离实验：真实创建临时 Job，核实普通子进程随宿主结束、独立交接后的进程继续运行；使用纯测试入口，不读取账号或启动真实桌面。
- 安装验证：只替换 CC Switch，核对当前账号、登录、设置、数据库及正在运行的 Codex 身份不变，确认唯一管理器和启动诊断。
- 完整流程：单独验证正常退出、启用、重开、身份核对及原聊天恢复。源码测试或安装成功不能代替此项。

## 后续崩溃自愈范围

任意阶段崩溃后的自动补完另行实施，需要持久化账号选择版本、实际退出确认、启用结果与新桌面回执，并逐项核对用户取消、手动改号、停任务和审批。不能仅凭旧 `close-intent` 自动关闭、切号或发送继续。本轮先预防已经复现的连带退出并补证据，不声称完整崩溃自愈已经实现。

## 2026-10-14：缩短关闭前流程

按后续确认的快速流程，关闭前改为一次元数据盘点并保存恢复清单，删除逐条暂停以及暂停后、退出前的两次全量盘点。初次读取只尝试一次，不把旧恢复核验的三次只读重试用于切号准备。临近正常退出时，只在原连接上最多观察 50 毫秒，已观察到用户停止、完成、审批、新轮次或设置变化的任务通过恢复记录比较提交排除。原运行任务同轮次、同设置刚刚出现明确额度失败时仍保留；不把它混为用户停止。

新清单使用 `DesktopShutdown` 来源，不能伪造为 CC Switch 已逐条暂停。原桌面正常退出并核实新桌面及账号后，才允许恢复同一清单轮次。无关审批或未知聊天留在停止状态，不再阻止切号。多个原聊天的加载准备并行，共用 90 秒期限，准备好的先恢复，恢复意图和发送仍顺序落盘，防止重复继续。账号已生效会先明确提示，剩余加载不再表述为仍在启用账号。

关闭前清单与退出之间仍可能发生极短的用户操作竞态；当前协议没有明确停止原因，不能宣称仅凭重开后的 `interrupted` 就能绝对区分。发送继续前仍核对原轮次、当前运行状态及保存设置，测试和实机验收需单独记录。

最终相关源码回归 235 项、启动判定 2 项、手动启用 3 项通过；纯 Windows Job 实验四组通过。本机 Codex 工具 Job 的原生交接曾被拒绝，原实例保留，之后使用 Explorer 独立入口启动。该管理器跨过当日自然额度触发及用户手动重开保持同一身份，三份完成记录均确认新桌面账号及 4 条原任务恢复，本聊天实际继续执行。统计修复的后续安装仅重开管理器，Codex 主进程保持不变；不以这些短期结果替代长期、锁屏和并发取消验收。
